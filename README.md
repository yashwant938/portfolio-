Personal software engineering portfolio, focused on IBM compiler experience,
Qualcomm ELD contributions, C++ systems, and applied generative AI.

Live website: https://yashwant938.github.io/portfolio-/

## Development

The site is prebuilt into `docs/`, with no JavaScript runtime dependencies.
Serve it locally using:

```sh
python scripts/build.py
python -m http.server 4173 --bind 127.0.0.1 --directory docs
```

Open http://127.0.0.1:4173. Edit `content/projects.json` for the five featured
projects and `content/index.template.html` for experience, hero, and page
structure. Edit `docs/style.css` for styling and `docs/app.js` for search,
filters, subtle motion, and legacy links. Run the build after changes and
commit the generated `docs/index.html`; CSS and JS URLs include content hashes.

The featured order is:

1. Qualcomm ELD Contributions
2. Legal Lens 2.0
3. C++ Concepts & Systems Lab — groups the interactive app and filesystem lab,
   preserving both source repositories and the live demo
4. GPT-2 Review Summarization
5. Real Estate Aggregator

Experience precedes projects, and the hero downloads the supplied resume at

## Preserved archive

`docs/archive.html`, `archive.css`, and `archive.js` preserve the earlier
14-project portfolio, its illustrations, links, and interactions.
`content/projects-archive.json` preserves that content snapshot. It is not
regenerated by the homepage build. The archive is labeled with its snapshot
date; PR links are authoritative for current status.

Incoming `#cpp-concepts` and `#filesystem-lab` links go to the merged C++ card.
Links to removed project IDs route to the relevant archived card.
`#contributions` opens the ELD evidence details. All five featured projects
and native details remain usable without JavaScript; filters and motion
controls appear only when JavaScript is enabled.

## Checks

With the preview server running:

```sh
npm install
npm test
```

The Playwright smoke test uses installed Microsoft Edge by default.
`BROWSER_CHANNEL=chrome` selects Chrome. `BASE_URL` can target a deployed
site and `QA_DIR` changes the screenshot/result directory.

Checks cover exact project order, IBM before projects, the resume PDF,
combined filters/search, empty/reset states, keyboard-operated details,
merged PR and C++ source links, image loads, legacy anchor routing, the
archive, motion preferences, no-JavaScript access, and page errors.
Open and closed details are checked for overflow at 320, 390, 768, and 1440px.
Desktop/mobile screenshots and a JSON report are saved to `test-results/`.
