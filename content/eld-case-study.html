CASE STUDY / MERGED PR #2207MERGED

A warning that points to the problem.

A linker combines compiled code into an executable. Its scripts can define symbols, but when the same symbol is declared again, the warning should help the developer find the conflicting line.

01 / THE INPUT

In the actual regression test, bar is defined and then declared again two lines later:

03  PROVIDE(bar = 3);
04  *(*foo*)
05  PROVIDE(bar = 5);
02 / BEFORE & AFTER

Previously the warning identified the file but left developers to search it. The fix includes the line of the repeated declaration:

BEFOREscript.t: Ignoring provide symbol 'bar' redeclaration
AFTERscript.t:5: Ignoring provide symbol 'bar' redeclaration

Warning paths shortened for readability; the diagnostic wording matches the regression test.

03 / THE FIX & PROOF

Changed the diagnostic to use the existing getContextWithLineNumber() helper. The updated ProvideSymbolRedecl test checks lines 5, 7, and 9; a second test checks a declaration outside SECTIONS.

Both tests failed before the fix and passed afterward across six target configurations: 12 focused passes, no skips. The full suite was not run.
